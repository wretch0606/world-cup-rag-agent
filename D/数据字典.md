### 球队 ID 编码规则

格式：`team_{FIFA_CODE}`

- 现存球队使用 FIFA 官方三字母码
- 历史球队按 FIFA 历史代码：`team_URS`（苏联）、`team_YUG`（南斯拉夫）、`team_TCH`（捷克斯洛伐克）、`team_GDR`（东德）、`team_FRG`（西德）、`team_DEI`（荷属东印度）、`team_ZAI`（扎伊尔）、`team_SCG`（塞尔维亚和黑山）

## 十二、Chroma 事实文本格式（C → D 契约）

`match_facts.jsonl` 每行一个 JSON，格式对齐 C→D Chroma 入库接口契约 v2.0：

```json
{
  "id": "match_fact_M-2022-64_v2",
  "text": "2022年世界杯决赛，阿根廷队在卢赛尔体育场与法国队90分钟内2:2战平、加时赛后3:3仍战平，点球大战阿根廷队4:2胜出晋级。",
  "metadata": {
    "match_id": "M-2022-64",
    "tournament_year": 2022,
    "stage": "final",
    "stage_name": "决赛",
    "team_ids": ["team_ARG", "team_FRA"],
    "result_type": "penalties",

    "source_ids": ["src_csv_20260716_001", "source-kaggle-001"],
    "document_name": "FIFA World Cup 2022",
    "source_url": "https://www.kaggle.com/datasets/...",
    "source_page": null,

    "chunk_index": 0,
    "language": "zh",
    "data_version": "2026-07-16-v2"
  }
}
```

> **v2 变更**: 新增 `id`（幂等更新 key）、`source_url`、`source_page`、`chunk_index`。`source_ids` 改为数组支持多来源。`stage` 使用英文 enum，`stage_name` 提供中文显示名。`source_ids` 在全链路保留到最终响应。

## 十四、已知限制

1. **12 场加时/点球比赛缺少进球数据**：无法自动计算 90 分钟比分，需人工对照 FIFA 官方数据修正。清单见 `score_fix_report.json` 中 `log` 部分。
2. **点球大战逐轮数据缺失**：goals 表中 `match_period='penalties'` 为 0，P2 的 `penalty_shootout_events` 表未启用。
3. **PDF 比赛报告未导入**：Chroma 的 `world_cup_reports` collection 需要另行采集文本文件。
4. **数据仅为 Kaggle 公开数据集**：未与 FIFA 官方记录做逐场交叉校验。建议在答辩/上线前至少对决赛和半决赛做人工核对。
5. **历史球队名称覆盖**：1950 年前的部分历史名称（如 `Dutch East Indies`）在别名表中仅有基本英文和中文映射。
